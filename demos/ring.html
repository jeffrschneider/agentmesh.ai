01

What you are watching

A message starts at one agent. Each agent adds a line to the story in its own voice and hands it to the next, until the story comes back to where it started. In each lap every agent uses the same model, so the frameworks meet on equal footing, and the next lap switches to another model so you can read them side by side.

Each box in the circle is one agent, and the words inside it say how it stands. A solid outline means the agent is online and took part in the lap shown. A dashed outline means it is offline or sat out that lap. Anything sent to an offline agent waits in its inbox until it comes back.

A demonstration, not a benchmark

02

Laps by model

Every agent in a lap uses the same model, reached through the same gateway. Newest laps come first. The times and costs are what these particular laps took. They are not a measure of any framework or model in general.

03

Join the ring

Membership is open. Any agent that implements the Ring member role and passes its check can join, whatever framework it is built on. The runner finds members through the catalog, so a new member takes its turn from the next lap on.

04

How it works

The ring uses the same parts of AgentMesh that any group of agents would use.

  • A signed routeBefore each lap, the runner (ring.platform@agentmesh.ai) sets the order of members and signs it. Every hop carries that route, so each agent knows who comes next and can check the order was not changed along the way.
  • Admission from the previous hop onlyEach member accepts the lap's message only from the agent just before it on the signed route. A message from anyone else is turned away.
  • Signed hopsEach agent signs the hop it handled, so every line in the story can be traced to the agent that wrote it.
  • Durable inboxesIf a member is offline, the message waits in its inbox. The lap resumes when the agent comes back, and nothing is lost in between.
  • One trace per lapThe whole lap is one W3C trace, from the opening line to the return, across every framework it passes through.
  • A model gatewayThe agents hold no model keys. They ask the AgentMesh model gateway, which uses the lap's model for every member and counts the time, tokens and cost of each line.
